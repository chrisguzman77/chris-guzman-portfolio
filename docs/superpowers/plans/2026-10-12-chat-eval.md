# Chat Quality Over Time Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every Sunday a GitHub Actions job runs the chat answer eval inside the deployed api container and records one `chat_eval_runs` row. Grafana charts the history, alerts on regressions and staleness, and the API exports a live `chat_answer_seconds` histogram.

**Architecture:**
- **API:** One Alembic migration adds the `chat_eval_kind` enum and the `chat_eval_runs` table. A new `portfolio_api/evals/scoring.py` holds the pure retrieval and latency scores (hit@5, MRR, nearest-rank percentile) and runs the golden set, which moves to `src/portfolio_api/evals/golden.yaml` so it ships in the image. A new `portfolio_api/evals/report.py` turns per-case results into the Markdown summary and the table row. `portfolio-api chat-eval` gains `--kind`, `--record` and `--summary-file`. `ChatService.ask` times `compose` into `chat_answer_seconds{outcome}`.
- **Ops:** `infra/postgres/init/03-grafana-chat-ro.sh` creates the `grafana_chat_ro` role (SELECT on `chat_eval_runs` and `chat_usage_daily` only). It runs at init and from `scripts/deploy.sh`. A `chat-readonly` Postgres datasource feeds the new "Chat quality" dashboard and three SQL alert rules. A child notification policy sends those alerts' reminders weekly instead of every 4 hours. CI's provisioning checks learn the new files.
- **Runner:** `.github/workflows/chat-eval.yml` runs on the VM's self-hosted runner. It calls `docker exec portfolio-api-1 portfolio-api chat-eval --kind <kind> --record --summary-file /tmp/chat-eval.md`, copies the summary out and appends it to the job summary.

**Tech Stack:** FastAPI, SQLAlchemy 2 (async), Alembic, pytest (via `uv`), prometheus-client, PyYAML; Postgres 17 (psql init scripts); Grafana 13 provisioning (Postgres datasource, file-provisioned alert rules and policies, dashboard JSON); GitHub Actions (self-hosted runner); bash + shellcheck.

**Spec:** `docs/superpowers/specs/2026-10-12-chat-quality-design.md`, section "PR 2: Quality over time", is binding except for the resolutions below. PR 1 (feedback, branch `feat/chat-feedback`, PR #59) is the base. PRs 3 and 4 are out of scope, but this PR leaves room for them: the `redteam` enum value, the workflow's `kind` input, a per-kind stale query and dashboard series split by kind.

**Spec resolutions (decided while planning):**
1. **The commit comes from `API_APP_VERSION`.** The spec says to reuse an existing build-time commit if there is one. `infra/compose/compose.yaml` already sets `API_APP_VERSION: ${IMAGE_TAG:?}`, and `deploy.sh` sets `IMAGE_TAG` to `${{ github.sha }}`. So the Dockerfile and `release.yml` don't change. `image_commit(settings.app_version)` returns the value only when it looks like a git SHA (`[0-9a-f]{7,40}`), so `dev` and `latest` (first deploy) are stored as NULL.
2. **`--kind redteam` exits 1 in this PR.** argparse accepts `answer|redteam`, so the workflow input and the CLI already have PR 3's shape. `redteam` prints `chat-eval: no redteam cases yet; only --kind answer runs` to stderr and exits 1, before it touches Groq or the database. The Wednesday cron doesn't exist until PR 3.
3. **Case ids and categories come from each case's position in `chat_eval.yaml`.** The cases have no ids today. Ids are `answerable-01` … `answerable-16` and `refuse-01` … `refuse-10`, and the categories are `answerable` and `refuse`. The YAML doesn't change, so `test_eval_cases_are_well_formed` and the existing judges stay as they are. PR 3's `redteam.yaml` carries explicit ids.
4. **The exit code stays 1/0.** The spec says "the number of failures, as today", but today `_chat_eval` returns `1 if failed else 0` (and a raw count would wrap at 256). The job fails on any failure either way.
5. **What gets timed and averaged.**
   - **Latency:** for each case, the time of the `compose` attempt that succeeded. Busy-retry sleeps aren't counted.
   - **Tokens per question:** the mean over cases that produced a `Composed`. `no_match` counts as 0 tokens.
   - **Excluded from both:** cases that never got an answer (`model busy after retries`, `model unavailable`). They still count as failures.
6. **Rates for kind `answer`.**
   - `answer_pass_rate` covers the 16 answerable cases.
   - `refusal_pass_rate` covers the 10 refuse cases.
   - `cases` and `passed` cover all 26.
   - Each rate is NULL when its group is empty.
   - PR 3 sets `refusal_pass_rate` over all redteam cases.
7. **`--record` reuses the CLI's sessionmaker.** That is the same `API_DATABASE_URL` the api uses. It writes one row in one transaction at the end of the run. The summary file is written first, so a database error still leaves the job summary.
8. **Eval tokens still go into `chat_usage_daily`.** `run_eval` keeps calling `service.record_usage`, so the visitor budget gate counts them. They aren't added to `chat_tokens_total`: the exec'd process has its own registry, which Prometheus never scrapes.
9. **Golden retrieval on the live index** runs after the cases. It uses the same `Retriever` (and embedder instance) as the `ChatService`, so it adds no model memory beyond today's `make chat-eval`. `hit_at_5` and `mrr` are NULL only if the golden set is empty.
10. **The golden test reports through `capsys.disabled()`.** That way the line shows in the CI log without `-s`. The test appends the same line to `$GITHUB_STEP_SUMMARY` through a sync helper, because ruff's `ASYNC230` and `ASYNC240` forbid blocking file I/O inside `async def`. The gate stays at `REQUIRED_HITS = 15`.
11. **How the runner reaches the api container.**
    - **docker exec:** the runner container mounts `/var/run/docker.sock` with `group_add: ["${DOCKER_GID}"]`, and `release.yml`'s deploy job already drives Docker this way. The compose project is `portfolio`, so the container is `portfolio-api-1`.
    - **/tmp:** the api service has no `read_only` or `tmpfs`, and `python:3.12-slim` has a world-writable `/tmp`, so user 1000 can write `/tmp/chat-eval.md`.
    - **Stale summaries:** the job deletes the old file first, copies the new one to `$RUNNER_TEMP`, and appends it with `if: always()`. A failing eval (exit 1) still publishes its table, and the job is red.
12. **Cron to kind.** A step maps `github.event.schedule` to a kind: `"30 8 * * 0"` means `answer`, and any other schedule fails the job loudly. Manual runs use the `kind` input. Both values pass through `env:`, never interpolated into the script.
13. **The alert rules are SQL plus a threshold, with no Reduce step.**
    - **Query shape:** each query returns a table with one numeric column (plus a string `kind` label column for stale). Grafana treats that as numeric data, so `threshold` reads it directly, like the existing instant-PromQL rules.
    - **Stale with zero rows:** `chat-eval-stale` must fire when there are no rows at all. Its query `LEFT JOIN`s a `VALUES ('answer')` list to the table and uses `COALESCE(…, 1000000)` hours, so it always returns one row per kind. PR 3 adds `('redteam')`.
    - **noData/execErr:** `noDataState: OK` for answer-low and refusal (no runs yet is stale's job), and `Alerting` for stale (its query can't return zero rows anyway). `execErrState: Error` for all three, like every existing rule.
    - **`for`:** `0s` for answer-low and refusal. `1h` for stale, which leaves time for the first manual run after the deploy.
    - **No dollar signs** appear in any rule (CI checks).
14. **Weekly reminders.** A firing chat-eval rule stays true until the next weekly run, so the root policy's 4-hour `repeat_interval` would send about 40 emails. The three rules carry the label `component: chat-eval`. A child route in `policies.yml` matches that label and sends to the same `email-chris` contact point with `repeat_interval: 168h`.
15. **What the role script grants and revokes.**
    - It grants `CONNECT ON DATABASE portfolio` explicitly, because `02-grafana-umami-ro.sh` already revoked `PUBLIC`'s connect there.
    - It also revokes `PUBLIC` connect on `umami`, `directus` and `portfolio`, which is idempotent. So the new role can't reach the other databases even while the umami password is unset. Owners and explicitly granted roles keep access.
16. **Migration up/down** is covered by PR 1's CI step `alembic downgrade -1 && alembic upgrade head`, which round-trips the newest migration (this one). The new DB test checks the table's columns.
17. **`failures` items are exactly `{id, category, reason}`.** PR 3 adds `known`.
18. **Dashboard latency and tokens series split by kind** (`kind::text AS metric`), so PR 3's redteam rows appear without editing the dashboard. Pass rates use one panel per kind, as the spec lists them.
19. **No CI job validates workflow files.** The new workflow is checked locally with `actionlint`, ignoring only the custom runner label.
20. **The secret must exist before merge.** Without `GRAFANA_CHAT_DB_PASSWORD` the datasource login fails. The dashboard shows errors and the three rules go to Error, which sends one DatasourceError email every 4 hours. Chris adds the key in a separate secrets PR, as with #49, before merging this one.

## Global Constraints

- **Table `chat_eval_runs`** (portfolio DB). Rows are kept forever, and nothing purges them.

  | Column | Type |
  |---|---|
  | `id` | uuid PK |
  | `kind` | enum `chat_eval_kind` (`answer`, `redteam`), not null |
  | `started_at`, `finished_at` | timestamptz, not null |
  | `commit` | text, nullable |
  | `cases`, `passed` | int, not null |
  | `answer_pass_rate`, `refusal_pass_rate` | float, nullable |
  | `hit_at_5`, `mrr` | float, nullable |
  | `latency_p50_ms`, `latency_p95_ms` | int, not null |
  | `tokens_per_question` | float, not null |
  | `failures` | jsonb, not null: a list of `{id, category, reason}` |

  The migration's `down_revision` is `c5d2f8a1e93b`, and its revision is `e4a1b7c3d826`.
- **Scores:**
  - **hit@5:** the share of golden questions with an expected title substring in the top 5 hits.
  - **MRR:** the mean of 1/rank of the first expected title, or 0 when none is in the top 5.
  - **Latency:** p50 and p95 by nearest rank, in whole milliseconds, over per-case `compose` time.
  - **`tokens_per_question`:** the mean of input + output tokens.
- **Golden set:** `apps/api/src/portfolio_api/evals/golden.yaml`, moved with `git mv` so history follows it. `tests/rag/test_golden.py` reads it from there and keeps `REQUIRED_HITS = 15`.
- **CLI:** `portfolio-api chat-eval [--kind answer|redteam] [--record] [--summary-file PATH]`. `--kind` defaults to `answer`, and `make chat-eval` is unchanged.
  - It always prints the per-case lines, then a blank line, then the Markdown summary.
  - `--summary-file` also writes the summary there, with a trailing newline.
  - `--record` writes one row.
  - The exit code is 1 if any case failed, otherwise 0.
- **Summary format:**
  - The heading is `## Chat eval (<kind>)`.
  - Next comes `<passed>/<cases> passed · <YYYY-MM-DD HH:MM UTC> · commit <first 7 of the SHA or "unknown">`.
  - Then a `| Score | Value |` table with Answer pass rate, Refusal pass rate, Retrieval hit@5, Retrieval MRR, Latency p50 / p95 and Tokens per question.
  - It ends with `No failed cases.`, or a `### Failed cases` table with the columns `| Case | Category | Question | Reason |`.
- **Metric:** a histogram `chat_answer_seconds{outcome}` with buckets `0.25, 0.5, 1, 2, 4, 8, 16`. It is observed around `compose` in `ChatService.ask`, for every outcome including `error`. All four children exist from startup.
- **Workflow `.github/workflows/chat-eval.yml`:**
  - **Triggers:** `schedule: "30 8 * * 0"` (answer), and `workflow_dispatch` with a choice input `kind` (`answer`, `redteam`; default `answer`). There's no Wednesday cron.
  - **Job settings:** `runs-on: [self-hosted, portfolio-deploy]`; `concurrency: { group: chat-eval, cancel-in-progress: false }`; `permissions: contents: read`.
  - **The eval command:** `docker exec portfolio-api-1 portfolio-api chat-eval --kind "${KIND}" --record --summary-file /tmp/chat-eval.md`.
- **Grafana role:**
  - `grafana_chat_ro` has `SELECT` on `public.chat_eval_runs` and `public.chat_usage_daily` only, in database `portfolio`, with `CONNECTION LIMIT 3`.
  - The script is `infra/postgres/init/03-grafana-chat-ro.sh`. It is idempotent and executable (git mode 100755).

```python
    assert mean_reciprocal_rank(ranks) == pytest.approx((1 + 0.5 + 0 + 0.25) / 4)

    assert percentile([3.0], 0.95) == 3.0
```

```python
"""Retrieval and latency scores for chat-eval and the golden test."""

import math
from collections.abc import Sequence
from dataclasses import dataclass
from importlib.resources import files
from typing import Any

import yaml

from portfolio_api.services.chat import SearchesIndex

HIT_K = 5  # hit@5: an expected title in the top 5 hits (the retriever returns at most 5)


def load_golden() -> list[dict[str, Any]]:
    text = files("portfolio_api.evals").joinpath("golden.yaml").read_text()
    cases: list[dict[str, Any]] = yaml.safe_load(text)
    return cases


def first_hit_rank(titles: Sequence[str], expect: Sequence[str]) -> int | None:
    """1-based rank of the first title containing an expected substring, within the top HIT_K."""
    for rank, title in enumerate(titles[:HIT_K], start=1):
        if any(e in title for e in expect):
            return rank
    return None


def hit_rate(ranks: Sequence[int | None]) -> float:
    """hit@5: the share of questions with an expected title in the top 5 (0.0 for none)."""
    return sum(r is not None for r in ranks) / len(ranks) if ranks else 0.0


def mean_reciprocal_rank(ranks: Sequence[int | None]) -> float:
    """MRR: the mean of 1/rank of the first expected title, 0 when none is in the top 5."""
    return sum(1 / r for r in ranks if r is not None) / len(ranks) if ranks else 0.0


def percentile(values: Sequence[float], q: float) -> float:
    """Nearest-rank percentile, q in (0, 1]; 0.0 when there are no values."""
    if not values:
        return 0.0
    ordered = sorted(values)
    return ordered[max(0, math.ceil(q * len(ordered)) - 1)]


@dataclass(frozen=True)
class GoldenResult:
    question: str
    titles: list[str]  # the retrieved hits' titles, best first
    rank: int | None


async def run_golden(
    retriever: SearchesIndex, cases: Sequence[dict[str, Any]]
) -> list[GoldenResult]:
    """Each golden question through retrieval only: no model call, no tokens."""
    results: list[GoldenResult] = []
    for case in cases:
        titles = [h.title for h in (await retriever.search(case["question"])).hits]
        results.append(
            GoldenResult(case["question"], titles, first_hit_rank(titles, case["expect"]))
        )
    return results
```

```python
"""One chat-eval run: per-case results, its scores, the Markdown summary and the history row."""

from dataclasses import dataclass
from datetime import UTC, datetime
from pathlib import Path

from portfolio_api.evals.scoring import percentile
from portfolio_api.models import ChatEvalKind, ChatEvalRun

ANSWERABLE = "answerable"
REFUSE = "refuse"


@dataclass(frozen=True)
class CaseResult:
    id: str  # from the case's place in the eval file: answerable-01, refuse-03, ...
    category: str
    question: str
    reason: str | None  # why it failed; None when it passed
    seconds: float | None  # compose time; None when the model never answered (busy, down)
    tokens: int  # input + output


@dataclass(frozen=True)
class EvalReport:
    kind: ChatEvalKind
    started_at: datetime
    finished_at: datetime
    commit: str | None
    results: list[CaseResult]
    hit_at_5: float | None
    mrr: float | None

    @property
    def failures(self) -> list[CaseResult]:
        return [r for r in self.results if r.reason is not None]

    @property
    def passed(self) -> int:
        return len(self.results) - len(self.failures)

    def pass_rate(self, category: str) -> float | None:
        group = [r for r in self.results if r.category == category]
        return sum(r.reason is None for r in group) / len(group) if group else None

    def latency_ms(self, q: float) -> int:
        timed = [r.seconds for r in self.results if r.seconds is not None]
        return round(1000 * percentile(timed, q))

    @property
    def tokens_per_question(self) -> float:
        answered = [r.tokens for r in self.results if r.seconds is not None]
        return sum(answered) / len(answered) if answered else 0.0


def _rate(value: float | None) -> str:
    return "n/a" if value is None else f"{value:.1%}"


def _score(value: float | None) -> str:
    return "n/a" if value is None else f"{value:.3f}"


def _cell(text: str) -> str:
    """One line, and no column breaks, inside a Markdown table cell."""
    return " ".join(text.split()).replace("|", "\\|")


def format_summary(report: EvalReport) -> str:
    when = report.started_at.astimezone(UTC).strftime("%Y-%m-%d %H:%M UTC")
    commit = report.commit[:7] if report.commit else "unknown"
    lines = [
        f"## Chat eval ({report.kind.value})",
        "",
        f"{report.passed}/{len(report.results)} passed · {when} · commit {commit}",
        "",
        "| Score | Value |",
        "|---|---|",
        f"| Answer pass rate | {_rate(report.pass_rate(ANSWERABLE))} |",
        f"| Refusal pass rate | {_rate(report.pass_rate(REFUSE))} |",
        f"| Retrieval hit@5 | {_score(report.hit_at_5)} |",
        f"| Retrieval MRR | {_score(report.mrr)} |",
        f"| Latency p50 / p95 | {report.latency_ms(0.5)} ms / {report.latency_ms(0.95)} ms |",
        f"| Tokens per question | {report.tokens_per_question:.0f} |",
        "",
    ]
    if not report.failures:
        lines.append("No failed cases.")
    else:
        lines += [
            "### Failed cases",
            "",
            "| Case | Category | Question | Reason |",
            "|---|---|---|---|",
        ]
        lines += [
            f"| {f.id} | {f.category} | {_cell(f.question)} | {_cell(f.reason or '')} |"
            for f in report.failures
        ]
    return "\n".join(lines)


def eval_run_row(report: EvalReport) -> ChatEvalRun:
    return ChatEvalRun(
        kind=report.kind,
        started_at=report.started_at,
        finished_at=report.finished_at,
        commit=report.commit,
        cases=len(report.results),
        passed=report.passed,
        answer_pass_rate=report.pass_rate(ANSWERABLE),
        refusal_pass_rate=report.pass_rate(REFUSE),
        hit_at_5=report.hit_at_5,
        mrr=report.mrr,
        latency_p50_ms=report.latency_ms(0.5),
        latency_p95_ms=report.latency_ms(0.95),
        tokens_per_question=report.tokens_per_question,
        failures=[
            {"id": f.id, "category": f.category, "reason": f.reason} for f in report.failures
        ],
    )


def write_summary(path: Path, summary: str) -> None:
    path.write_text(summary + "\n")
```

```python
async def _compose_with_retry(
    service: ChatService,
    question: str,
    busy_wait: float,
    sleep: Callable[[float], Awaitable[None]],
    timer: Callable[[], float],
) -> tuple[Composed, float] | str:
    """The answer and how long its (successful) attempt took, or why there is no answer."""
    for attempt in range(BUSY_RETRIES + 1):
        started = timer()
        try:
            composed = await service.compose(question, [])
        except ModelBusyError:
            if attempt == BUSY_RETRIES:
                return "model busy after retries"
            await sleep(busy_wait)  # free tier allows ~8,000 tokens a minute
            continue
        except ModelUnavailableError as exc:
            return f"model unavailable: {exc}"
        return composed, timer() - started
    return "unreachable"


async def run_eval(
    service: ChatService,
    cases: dict[str, Any],
    *,
    busy_wait: float = 30.0,
    sleep: Callable[[float], Awaitable[None]] = asyncio.sleep,
    out: Callable[[str], None] = print,
    timer: Callable[[], float] = time.perf_counter,
) -> list[CaseResult]:
    """Ask every case, print PASS/FAIL with the answer, return each case's result."""
    work: list[tuple[str, str, str, Callable[[Composed], str | None]]] = [
        (f"{ANSWERABLE}-{i:02d}", ANSWERABLE, c["question"], partial(judge_answerable, c))
        for i, c in enumerate(cases["answerable"], start=1)
    ] + [
        (f"{REFUSE}-{i:02d}", REFUSE, q, judge_refusal)
        for i, q in enumerate(cases["refuse"], start=1)
    ]
    results: list[CaseResult] = []
    for case_id, category, question, judge in work:
        attempt = await _compose_with_retry(service, question, busy_wait, sleep, timer)
        if isinstance(attempt, str):
            result = CaseResult(case_id, category, question, attempt, None, 0)
            answer = ""
        else:
            composed, seconds = attempt
            tokens = composed.input_tokens + composed.output_tokens
            if composed.raw is not None:
                await service.record_usage(tokens)
            result = CaseResult(case_id, category, question, judge(composed), seconds, tokens)
            answer = composed.answer
        results.append(result)
        status = "PASS" if result.reason is None else "FAIL"
        out(f"{status}  {question}" + (f"  ({result.reason})" if result.reason else ""))
        if answer:
            out(f"      {answer}")
    failed = sum(r.reason is not None for r in results)
    out(f"{len(work) - failed}/{len(work)} passed")
    return results


_SHA = re.compile(r"[0-9a-f]{7,40}")


def image_commit(version: str) -> str | None:
    """Compose sets API_APP_VERSION to the deployed image tag: a git SHA, or dev/latest."""
    return version if _SHA.fullmatch(version) else None


async def evaluate(
    service: ChatService,
    retriever: SearchesIndex,
    *,
    cases: dict[str, Any],
    golden: Sequence[dict[str, Any]],
    commit: str | None,
    record: async_sessionmaker[AsyncSession] | None = None,
    summary_file: Path | None = None,
    out: Callable[[str], None] = print,
    timer: Callable[[], float] = time.perf_counter,
) -> int:
    """The answer cases, then the golden questions through retrieval only (no tokens).

    Prints the Markdown summary, writes it to ``summary_file`` and one chat_eval_runs row
    through ``record`` when given, and returns the number of failed cases.
    """
    started_at = datetime.now(UTC)
    results = await run_eval(service, cases, out=out, timer=timer)
    ranks = [g.rank for g in await run_golden(retriever, golden)]
    report = EvalReport(
        kind=ChatEvalKind.answer,
        started_at=started_at,
        finished_at=datetime.now(UTC),
        commit=commit,
        results=results,
        hit_at_5=hit_rate(ranks) if ranks else None,
        mrr=mean_reciprocal_rank(ranks) if ranks else None,
    )
    summary = format_summary(report)
    out("")
    out(summary)
    if summary_file is not None:
        write_summary(summary_file, summary)  # first, so a database error still leaves it
    if record is not None:
        async with record.begin() as session:
            session.add(eval_run_row(report))
    return len(report.failures)
```

```bash
#!/usr/bin/env bash
# Read-only login for Grafana's Chat quality dashboard and chat-eval alerts: SELECT on the
# portfolio database's chat_eval_runs and chat_usage_daily tables and nothing else.
# Idempotent. It runs as an init script on a fresh data directory and again on every deploy
# (scripts/deploy.sh, after migrations), which covers the existing database, a changed
# password, and the grants once the API's migrations have created the tables.
# Skipped while GRAFANA_CHAT_DB_PASSWORD is unset. Must stay executable: the postgres
# entrypoint sources non-executable init scripts, and the exit below would end it.
set -euo pipefail

if [[ -z "${GRAFANA_CHAT_DB_PASSWORD:-}" ]]; then
  echo "grafana_chat_ro: skipped (GRAFANA_CHAT_DB_PASSWORD not set)"
  exit 0
fi

psql -v ON_ERROR_STOP=1 --username "${POSTGRES_USER}" --dbname portfolio \
  --set=pw="${GRAFANA_CHAT_DB_PASSWORD}" <<'SQL'
SELECT NOT EXISTS (SELECT FROM pg_roles WHERE rolname = 'grafana_chat_ro') AS missing \gset
\if :missing
CREATE ROLE grafana_chat_ro;
\endif
ALTER ROLE grafana_chat_ro WITH LOGIN CONNECTION LIMIT 3 PASSWORD :'pw';
GRANT CONNECT ON DATABASE portfolio TO grafana_chat_ro;
-- Owners keep access; only roles without an explicit grant (this one) lose connect.
REVOKE CONNECT ON DATABASE portfolio FROM PUBLIC;
REVOKE CONNECT ON DATABASE directus FROM PUBLIC;
REVOKE CONNECT ON DATABASE umami FROM PUBLIC;
SELECT to_regclass('public.chat_eval_runs') IS NOT NULL
   AND to_regclass('public.chat_usage_daily') IS NOT NULL AS has_tables \gset
\if :has_tables
GRANT SELECT ON public.chat_eval_runs, public.chat_usage_daily TO grafana_chat_ro;
\else
\echo 'grafana_chat_ro: chat tables do not exist yet; the next deploy grants them'
\endif
SQL
echo "grafana_chat_ro: ok"
```

Create `.github/workflows/chat-eval.yml`:

```yaml
name: chat-eval

# The chat answer eval, run inside the deployed api container by the VM's self-hosted
# runner (docker.sock; see docs/adr/0006-runner-in-compose.md). Each run is recorded in
# chat_eval_runs (Grafana → Chat quality); alerts come from Grafana, not this job's status.
# A red job means at least one case failed: read the summary. Scheduled runs use the
# default branch only.
on:
  schedule:
    - cron: "30 8 * * 0" # answer eval, Sunday 08:30 UTC
  workflow_dispatch:
    inputs:
      kind:
        description: Which eval to run
        type: choice
        options: [answer, redteam]
        default: answer

permissions:
  contents: read

concurrency:
  group: chat-eval
  cancel-in-progress: false

defaults:
  run:
    shell: bash

jobs:
  eval:
    runs-on: [self-hosted, portfolio-deploy]
    timeout-minutes: 45
    steps:
      - name: Pick the kind
        id: kind
        env:
          EVENT: ${{ github.event_name }}
          SCHEDULE: ${{ github.event.schedule }}
          INPUT_KIND: ${{ inputs.kind }}
        run: |
          if [[ "${EVENT}" == schedule ]]; then
            case "${SCHEDULE}" in
              "30 8 * * 0") kind=answer ;;
              *) echo "no kind for schedule '${SCHEDULE}'" >&2; exit 1 ;;
            esac
          else
            kind="${INPUT_KIND}"
          fi
          echo "kind=${kind}" >> "${GITHUB_OUTPUT}"
      - name: Clear the last summary
        run: docker exec portfolio-api-1 rm -f /tmp/chat-eval.md
      - name: Run the eval in the api container
        env:
          KIND: ${{ steps.kind.outputs.kind }}
        run: docker exec portfolio-api-1 portfolio-api chat-eval --kind "${KIND}" --record --summary-file /tmp/chat-eval.md
      - name: Add the summary to this run's page
        if: always()
        run: |
          if docker cp portfolio-api-1:/tmp/chat-eval.md "${RUNNER_TEMP}/chat-eval.md"; then
            cat "${RUNNER_TEMP}/chat-eval.md" >> "${GITHUB_STEP_SUMMARY}"
          else
            echo "No summary was written; the eval stopped early. See the eval step's log." >> "${GITHUB_STEP_SUMMARY}"
          fi
```
